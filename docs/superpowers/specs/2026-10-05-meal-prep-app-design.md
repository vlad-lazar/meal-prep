# Meal Prep — iOS App Design Spec

Date: 2026-10-05
Status: Approved in chat, pending written-spec review

## 1. Purpose

A personal-use native iOS app (iPhone 16, sideloaded via Xcode — not App Store) for meal prepping on a budget in Denmark.
The user picks one meal by approximate DKK per portion, cooking time and difficulty, chooses how many portions to prep,
and the app finds the cheapest nearby grocery store for that meal, produces a shopping list using live store offers,
then guides cooking step by step. Nutrition facts per portion are shown.

### Success criteria

- Browsing meals shows a DKK/portion figure, cooking time and difficulty for every meal, filterable on all three.
- For a chosen meal and portion count, nearby grocery stores are ranked by total basket price, using live weekly offers
  where available and typical prices otherwise, with each line clearly marked as "offer" or "estimate".
- The selected store's shopping list can be checked off and leads into a step-by-step cook mode with timers.
- Nutrition (kcal, protein, carbs, fat, fibre) per portion is shown for every meal.
- The app never blocks on network or location failures; it degrades to estimates.
- Colourful, clean UI with smooth animations; supports light/dark mode and Reduce Motion.

### Decisions made

| Topic | Decision |
|---|---|
| Price data | Live weekly offers (Tjek/eTilbudsavis) + bundled typical-price table for non-discounted items |
| Recipes | Bundled curated library (~40 recipes, JSON) |
| Store choice | Cheapest single store; whole list from one store |
| Scope | One meal × N portions per prep; history + favourites |
| Architecture | Fully on-device; no backend |

### Out of scope (v1)

Weekly multi-meal planning, multi-store basket split, AI-generated recipes, backend service, widgets, Apple Watch,
App Store distribution, Salling Group API (requires key; possible later addition).

## 2. Platform & tooling

- Swift 6, SwiftUI, iOS 18.0 minimum deployment target, iPhone only, portrait.
- State: `@Observable` view models; SwiftData for persisted user data (`PrepSession`, favourites, settings).
- Networking: `URLSession` + async/await; no third-party dependencies.
- Project generated by XcodeGen from `project.yml` (`MealPrep.xcodeproj` is git-ignored and regenerated).
- Targets: `MealPrep` (app), `MealPrepTests` (XCTest unit tests).
- Prerequisite on the dev Mac: full Xcode (currently only Command Line Tools are installed) and `brew install xcodegen`.

## 3. Architecture

Single app target, organised into folders with one responsibility each. Services are protocols with live and mock
implementations so view models and tests can inject fakes.

```
MealPrep/
  App/            MealPrepApp, RootView (tab bar), AppEnvironment (DI container)
  Catalog/        CatalogStore — loads bundled JSON (recipes, ingredients, nutrition)
  Location/       LocationService — CLLocationManager wrapper + postcode fallback (CLGeocoder)
  Stores/         StoreService — nearby grocery stores via Tjek /v2/stores; ChainBranding
  Offers/         TjekClient, OfferService, OfferCache (disk, 12 h TTL)
  Pricing/        UnitConverter, OfferMatcher, BasketPricer, StoreRanker
  Nutrition/      NutritionCalculator
  Persistence/    SwiftData models: PrepSession, FavouriteRecipe, UserSettings
  Features/
    Onboarding/   OnboardingView
    Meals/        MealsView, MealCard, FilterBar, MealDetailView, NutritionCard
    Stores/       StoreComparisonView, StoreRow
    Shopping/     ShoppingListView, ShoppingRow
    Cook/         CookModeView, StepCard, StepTimer, PrepDoneView
    History/      HistoryView
  DesignSystem/   Palette, Gradients, Typography, Card, Chip, Shimmer, Haptics, Confetti
  Resources/      recipes.json, ingredients.json, nutrition.json, Assets.xcassets
MealPrepTests/
  Fixtures/       recorded Tjek JSON responses
```

### Data flow

1. Location (GPS or postcode) → `StoreService` returns nearby grocery `Store`s (3 km radius, widened to 10 km if empty).
2. Meals list initially prices each recipe from typical prices (instant), then — once offers are loaded — reprices with
   live offers for the nearby chains (animated numeric transition).
3. Meal detail → "Find stores" → `OfferService` fetches offers for the recipe's ingredients near the user (cached) →
   `BasketPricer` builds a `Basket` per store → `StoreRanker` sorts by total.
4. User picks a store → `ShoppingListView` → `CookModeView` → on finish, a `PrepSession` is saved.

## 4. Data model

### Bundled (read-only, JSON in `Resources/`)

```swift
struct Recipe: Codable, Identifiable {
  let id: String                // "chicken-curry"
  let name: String
  let cuisine: String           // "Indian", "Danish", ...
  let emoji: String             // header illustration
  let gradient: [String]        // two hex colours
  let minutes: Int              // total active + passive
  let difficulty: Difficulty    // easy=1, medium=2, hard=3
  let basePortions: Int
  let ingredients: [RecipeIngredient]
  let steps: [Step]
  let storageTip: String        // how to portion/store the prep
}
struct RecipeIngredient: Codable { let ingredientId: String; let amount: Double; let unit: Unit; let note: String? }
struct Step: Codable { let text: String; let timerSeconds: Int? }

struct Ingredient: Codable, Identifiable {
  let id: String                // "chicken-breast"
  let name: String              // English display name
  let danishName: String        // "Kyllingebryst"
  let searchTerms: [String]     // Tjek query terms, e.g. ["kyllingebryst", "kyllingebrystfilet"]
  let excludeTerms: [String]    // e.g. ["pålæg", "røget", "nuggets"]
  let section: ShopSection      // produce, meat, fish, dairy, bakery, dry, frozen, spices
  let isPantry: Bool            // oil, salt, spices: "have at home?"
  let typicalPack: Pack         // e.g. 500 g for 45.00 DKK
  let gramsPerPiece: Double?    // for converting pcs <-> g
  let mlDensity: Double?        // g per ml, for liquids
  let nutritionId: String       // key into nutrition.json
}
struct Pack: Codable { let amount: Double; let unit: Unit; let priceDKK: Double }
enum Unit: String, Codable { case g, kg, ml, l, pcs, tbsp, tsp }

struct NutritionPer100g: Codable { let kcal, protein, carbs, fat, fibre: Double }  // from DTU Frida
```

### Runtime

```swift
struct Store: Identifiable { let id: String; let chain: Chain; let name: String; let address: String;
                             let coordinate: CLLocationCoordinate2D; let distanceMeters: Double; let dealerId: String }
enum Chain { case netto, rema1000, lidl, foetex, bilka, coop365, kvickly, superbrugsen, dagliBrugsen, meny, spar, lovbjerg, other(String) }

struct Offer { let id: String; let heading: String; let description: String?; let dealerId: String
               let price: Double; let prePrice: Double?; let packAmount: Double; let packUnit: Unit
               let pieces: Int; let validUntil: Date; let imageURL: URL? }

enum PriceSource { case offer(Offer), typical }
struct PricedLine { let ingredient: Ingredient; let neededAmount: Double; let neededUnit: Unit
                    let packsToBuy: Int; let packPrice: Double; let lineTotal: Double   // packs × price
                    let usedCost: Double                                               // share actually used
                    let source: PriceSource; var isChecked: Bool }
struct Basket { let store: Store?; let lines: [PricedLine]; let portions: Int
                var shoppingTotal: Double; var mealCost: Double; var costPerPortion: Double
                var offerCount: Int; var estimateCount: Int }
```

### Persisted (SwiftData)

- `PrepSession`: id, date, recipeId, portions, storeName, chain, shoppingTotal, costPerPortion.
- `FavouriteRecipe`: recipeId.
- `UserSettings`: fallbackPostcode, fallbackCoordinate, hasOnboarded, pantryOverrides (ingredient ids the user does
  NOT have at home).

## 5. External services

### Tjek / eTilbudsavis (no key required; verified 2026-10-05)

- Stores: `GET https://squid-api.tjek.com/v2/stores?r_lat=&r_lng=&r_radius=&limit=` → filter by `branding.name` /
  `dealer_id` against a grocery-chain allowlist in `ChainBranding`. Dedupe by store id.
- Offers: `GET https://squid-api.tjek.com/v2/offers/search?query=&r_lat=&r_lng=&r_radius=&limit=` → fields used:
  `heading`, `description`, `pricing.price`, `pricing.pre_price`, `quantity.unit.symbol`, `quantity.unit.si.factor`,
  `quantity.size.from/to`, `quantity.pieces.from`, `dealer_id`, `run_till`, `images.thumb`.
- Requests: one per ingredient search term, max 4 concurrent, 10 s timeout; results unioned and deduped by offer id.
- Offers are per chain (dealer), not per store; every store of a chain gets the chain's offers.
- `OfferCache`: JSON on disk keyed by (search term, rounded lat/lng to 0.01°), TTL 12 h; stale cache is still used
  when the network fails, with its age shown in the UI.

### Apple

- CoreLocation: "When In Use" permission with purpose string "Used to find grocery stores near you."
- CLGeocoder: geocode the fallback Danish postcode once.
- UserNotifications: local notifications for cook-mode timers (permission requested on first timer start).

## 6. Pricing logic

### UnitConverter
Converts between g/kg, ml/l, tbsp (15 ml), tsp (5 ml), pcs (via `gramsPerPiece`), and ml↔g (via `mlDensity`).
Returns `nil` when no conversion path exists.

### OfferMatcher
An offer matches an ingredient when all hold:
1. Heading (lowercased, diacritics preserved) contains at least one `searchTerms` entry.
2. Heading and description contain none of `excludeTerms`.
3. Offer pack unit converts to the ingredient's base unit.
4. Offer price per kg/l/pc is within 0.3×–3× of the typical pack's price per kg/l/pc.
5. `run_till` is in the future.

For size ranges (`size.from`–`to`), the **smallest** size is used (conservative). If the description states a per-kg
maximum ("Pr. kg maks. 64,95"), that's informational only. Multi-buy offers use the single-item price if given;
otherwise the offer price divided by pieces. Among matching offers for a chain, the cheapest per base unit wins.

### BasketPricer
For each recipe ingredient scaled by `portions / basePortions`:
- Choose the source: the chain's best matching offer, else the typical pack.
- `packsToBuy = ceil(needed / packAmount)`; `lineTotal = packsToBuy × packPrice`;
  `usedCost = needed / packAmount × packPrice`.
- Pantry ingredients are excluded from totals unless listed in `pantryOverrides`.
- `shoppingTotal = Σ lineTotal`; `mealCost = Σ usedCost`; `costPerPortion = mealCost / portions`.

Browse-screen DKK/portion uses `costPerPortion` (cost of what's consumed), computed with typical prices, then the
cheapest nearby chain's price once offers load.

### StoreRanker
Sort baskets by `shoppingTotal` ascending, tie-break by distance. Badge the first as "Best price".

## 7. Nutrition

`NutritionCalculator`: for each ingredient, grams = converted needed amount; sum
`grams / 100 × NutritionPer100g`; divide by portions. Pantry items are included (oil matters for kcal).
Source: DTU Fødevareinstituttet Frida food database (CC BY 4.0), trimmed to used ingredients, attributed in About.

## 8. Screens

1. **Onboarding** (first launch): three swipeable gradient cards; the last requests location permission. Denied →
   postcode entry sheet.
2. **Meals tab**: greeting + location chip (tap to change); search field; filter chips (max kr/portion slider, max
   minutes slider, difficulty, cuisine); "Cheap this week" horizontal carousel ranked by live cost/portion;
   2-column grid of all meals. Cards: recipe gradient, emoji, name, kr/portion · minutes · difficulty dots,
   "🏷 on offer" badge when ≥1 ingredient has a nearby offer, favourite heart.
3. **Meal detail**: collapsing gradient header; portion stepper (2–12, default basePortions); stat pills; scaled
   ingredient list; NutritionCard (kcal ring, protein/carbs/fat bars, fibre) per portion; steps preview; storage
   tip; sticky "Find stores" button.
4. **Store comparison**: shimmer skeletons while loading; rows with chain colour stripe/logo-badge, name, distance,
   total, kr/portion, "N on offer · M estimated"; "Best price" badge; expandable row listing offer items;
   "Use this store" button. Banner when offers are stale or estimates-only.
5. **Shopping list** (Prep tab holds the active one): grouped by ShopSection; row: name, packs to buy, price, tag
   "Offer · until Sun" or "≈ estimate"; tap to check with strike-through + haptic; collapsible "Have at home?" pantry
   section with toggles feeding totals; running total; "Start cooking" button. Active list persists across launches.
6. **Cook mode**: full-screen paged step cards, large type, idle timer disabled; steps with `timerSeconds` show a
   start/pause ring timer that schedules a local notification; final "Prep done 🎉" screen with confetti, storage
   tip, and portion split ("N containers of ~X g"); saves PrepSession.
7. **History tab**: list of PrepSessions (date, recipe emoji/name, store, total, kr/portion), favourites section,
   "Prep again" (opens detail with same portions), "Spent this month" summary card.

## 9. Visual design & motion

- Per-recipe two-colour gradients drive colour on cards and detail headers; the rest of the UI is neutral
  (system grouped background, 20 pt corner radius cards, generous spacing).
- Typography: SF Pro Rounded for titles and numbers; SF Pro for body. SF Symbols throughout.
- Chain brand colours on store rows (`ChainBranding`).
- Light and dark mode; Dynamic Type supported up to accessibility sizes on core screens.
- Motion: iOS 18 `.navigationTransition(.zoom)` from card to detail; `.contentTransition(.numericText())` for prices;
  spring animations on list changes and check-offs; `symbolEffect(.bounce)` on chips/hearts; shimmer skeletons for
  loading; confetti on prep done; haptics (selection on check, success on step/timer finish).
- All non-essential animation disabled/reduced when `accessibilityReduceMotion` is on.

## 10. Error handling

| Situation | Behaviour |
|---|---|
| Location denied/unavailable | Postcode sheet; stored fallback coordinate; banner to change |
| Tjek network error / timeout / 429 | Use stale cache with "Offers from X ago"; if none, all lines typical with "Prices are estimates" banner |
| No grocery stores within 3 km | Retry at 10 km; if still none, show per-chain estimated totals without store rows |
| Offer fails matching rules | Ignored; line falls back to typical |
| Unit not convertible | Line priced from typical pack; logged in debug builds |
| Expired offers | Filtered by `run_till` |
| Decoding error on a single offer | Skip that offer, keep the rest (lossy array decoding) |
| Notification permission denied | Timers still run in-app; no background alert |

## 11. Recipe library v1

~40 meal-prep-friendly recipes using ingredients common in Netto/Rema/Lidl, spanning easy/medium/hard, mostly
20–60 min, targeting ~15–45 kr/portion. Examples: chicken curry with rice, chili con carne, frikadeller with potatoes
and gravy, pasta bolognese, teriyaki salmon bowls, red lentil dal, burrito bowls, chicken shawarma with bulgur,
overnight oats jars, pork stir-fry with noodles, vegetable lasagne, Thai green curry, meatballs in tomato sauce,
chicken & sweet potato traybake, tuna pasta salad. Typical prices are best-effort 2026 Danish discount-chain prices,
editable in `ingredients.json`.

## 12. Testing

XCTest unit tests (no live network):
- `UnitConverterTests`: all conversion paths and nil cases.
- `OfferMatcherTests`: search/exclude terms, unit conversion, sanity bounds, expiry, size ranges, multi-buy.
- `BasketPricerTests`: portion scaling, pack rounding, usedCost vs lineTotal, pantry exclusion/override, offer vs
  typical choice.
- `StoreRankerTests`: ordering and distance tie-break.
- `NutritionCalculatorTests`: per-portion scaling, unit conversion.
- `TjekDecodingTests`: decode recorded fixtures (stores + offers), lossy decoding of malformed items.
- `CatalogLintTests`: every recipe ingredient exists, has typical pack and nutrition entry, units convertible,
  gradients are valid hex, steps non-empty.
UI verified via SwiftUI previews with mock services, the iOS Simulator, and on-device runs. No UI tests.

## 13. Installation (README)

1. Install Xcode from the App Store; `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`.
2. `brew install xcodegen && xcodegen` in the repo root.
3. Open `MealPrep.xcodeproj`, set Signing to your Personal Team, set a unique bundle id.
4. iPhone: enable Developer Mode, connect via cable, Run; trust the developer certificate in
   Settings → General → VPN & Device Management.
5. Free Apple ID builds expire after 7 days — re-run from Xcode to refresh.
